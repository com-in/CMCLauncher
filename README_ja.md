# CMCLauncher

<div align="center">

[English](README.md) · [简体中文](README_zh.md) · [日本語](README_ja.md)

</div>

Minecraft Java Edition 向けのネイティブ Windows ランチャーです。C#、.NET 8、WinUI 3 で構築されています。分離インスタンスの管理、ゲームバージョンとローダーのダウンロード、Modrinth / CurseForge コンテンツの導入、Java とアカウントの管理に対応しています。

現在のバージョン：**1.0.0** · プラットフォーム：**Windows x64**

[ダウンロード](https://github.com/com-in/CMCLauncher/releases) · [Web サイト](https://cmcl.ctfun.top/) · [問題の報告](https://github.com/com-in/CMCLauncher/issues)

![CMCLauncher 英語ホーム画面](docs/assets/launcher-home.png)

## クイックスタート

1. [Releases](https://github.com/com-in/CMCLauncher/releases) から `CMCLauncher-1.0.0-win-x64.zip` をダウンロードし、アーカイブ全体を展開して `CMCLauncher.exe` を実行します。
2. **設定 → Java** を開き、既存の Java インストールをスキャン／インポートするか、Temurin Java をダウンロードします。
3. **設定 → アカウント** を開き、Microsoft デバイスコードサインインを選びます。ブラウザで認証を完了し、ランチャーがあなたの Minecraft Java プロフィールを検証するのを待ちます。
4. ゲームバージョンをダウンロードするか、既存の `.minecraft` フォルダをインポートするか、統合パックをインポートします。ホームでバージョンとアカウントを選んで起動します。

**設定 → アカウント** では、Microsoft アカウントが Minecraft Java プロフィール検証を通過した後、外部サインイン（authlib-injector）を利用できます。Yggdrasil サーバーの URL とそのサーバーの認証情報を入力し、必要に応じてプレイヤープロフィールを選択します。ランチャーは暗号化されたセッショントークンを保存し、起動時に authlib-injector をダウンロード・検証します。また、アカウントリストに検証済み Microsoft アカウントが残っていることを要求します。最後に検証済みの Microsoft アカウントを削除すると、Microsoft 検証が復元されるまで外部アカウントはロックされます。

リリースアーカイブには .NET と Windows App SDK ランタイムが含まれているため、.NET を別途インストールする必要はありません。Java とゲームファイルは個別にダウンロードまたはインポートします。ランチャーは既定で起動時に GitHub Releases を確認します。**ランチャー設定 → ランチャー更新** で、起動時チェックの無効化、手動チェック、ベータ版への参加ができます。**更新をダウンロードしてインストール** を選ぶと、GitHub の SHA-256 ダイジェストでパッケージを検証し、ランチャーを閉じて更新をインストールし再起動します。進行中のタスクとゲームは先に終わらせる必要があります。アカウント、インスタンス、設定、既存の言語／テーマファイルは保持されます。インストールフォルダは書き込み可能である必要があります。置き換えに失敗した場合はバックアップファイルの復元が試みられ、診断とバックアップは `%LOCALAPPDATA%/CMCLauncher/updates/` に置かれます。互換パッケージや SHA-256 ダイジェストのないリリースは、**リリースノートを表示** から手動でダウンロードします。ベータを無効にすると今後のチェックに影響し、インストール済みバージョンをダウングレードすることはありません。

### 動作環境

- Windows 10 バージョン 2004（ビルド 19041）以降、x64。
- 選択した Minecraft バージョンに互換する Java ランタイム。ランチャーは起動時に検出された Java インストールをチェック・照合します。
- Microsoft サインイン用に Minecraft Java エディションのプロフィールを持つ Microsoft アカウント。オフラインID が使えるようになるには、少なくとも 1 つの Microsoft アカウントが検証を通過している必要があります。

## 機能

| 領域 | 対応機能 |
| --- | --- |
| ゲームとインスタンス | リリース、スナップショット、エイプリルフールバージョンの閲覧；分離インスタンスの作成；ローカルゲームフォルダのインポート |
| ローダー | Fabric、Forge、NeoForge の検索とインストール；インポートしたバージョンのローダー識別 |
| 統合パック | Modrinth `.mrpack` ファイル、対応マニフェストを含む ZIP アーカイブ、MultiMC / Prism の ZIP エクスポートのインポート；ドラッグ＆ドロップインポート |
| コミュニティコンテンツ | Modrinth、CurseForge、または両方を選択；ページ送り結果の閲覧、プロジェクトバージョン表示、ゲーム・ローダー・導入先の互換性確認 |
| コンテンツ管理 | Mod のメタデータとアイコンの確認；コンテンツのインポート・無効化・削除；ワールド別のデータパック管理 |
| スケマティック | `.litematic`、`.schematic`、`.schem`、`.nbt` ファイル（入れ子フォルダを含む）の検索・インポート・エクスポート・名前変更・削除 |
| Java とメモリ | Temurin Java のスキャン・インポート・ダウンロード；Java バージョンの自動照合；自動または手動のヒープ割り当て |
| ダウンロード | 進行状況と速度の表示、タスクのキャンセル、同時ダウンロード数 1–256 の設定（既定：16） |
| Frp クライアント | 公式 Windows x64 リリースのダウンロード、INI/TOML 設定の検証、クライアントの起動／停止と出力の表示 |
| 外観と言語 | ライト・ダーク・システムテーマ；色、フォント、スケール、外観プリセット；ランチャーとゲームの言語設定 |
| アカウントと診断 | Microsoft デバイスコードサインイン、外部 authlib-injector サインイン、Windows DPAPI 資格情報の暗号化、ランタイムログ、ゲームエラーレポートのエクスポート |

新しいインスタンスは Mod、セーブ、設定を相互に独立して保持します。インポートしたゲームは、認識されたバージョン分離レイアウトを含め、元の場所を維持します。

ローカルインポートでは、PCL/HMCL ランチャーフォルダ、`.minecraft`、`versions`、または個々の `versions/<id>` フォルダを選択できます。CMCLauncher は PCL の分離設定と説明／お気に入り／アイコンメタデータ、レガシー HMCL の `hmclversion.cfg`、現在の `.hmcl/config/instance-game-settings.json` のディレクトリ上書きを読み取ります。明示的な分離とカスタム実行ディレクトリはフォルダの検出より優先されます。HMCL のゲームコンポーネントメタデータは名前を変更した Minecraft プロフィールも識別します。新しい分離インスタンスには、互換性のある PCL とレガシー／現在の HMCL 分離メタデータが書き込まれます。検出はローカルのプロフィールのみを使用し、ソースファイルは元の場所に保持されます。ランチャー全体の設定と資格情報は各ランチャーで管理されます。

インターフェース翻訳は、実行ファイルの横にある `locales/` の編集可能な JSON ファイルから読み込まれ、組み込みのフォールバックコピーがあります。追加の有効な言語パックは言語セレクタに表示されます。スキーマ、再読み込み動作、翻訳ガイドラインについては [インターフェース言語パック](docs/LOCALIZATION.md) を参照してください。

完了したタスクは画面下部中央に一時的なトーストとして表示されます。キャンセル・失敗したタスクの結果もそこに表示されます。削除はアクションの隣の確認ポップオーバーを使用します。閉じたポップオーバーはファイルを変更しません。

スケマティックは、既存の `schematics` フォルダを持つ mod インスタンスのバージョン設定に表示されます。フォルダがない場合、ランチャーは有効な Mod メタデータとサポートされている Litematica/Schematica 移植版または Create を確認し、検出時にフォルダを作成します。バニラインスタンスではこのページは非表示になります。ファイル管理は元の形式を保持します。特定のスケマティックとの互換性は、導入された Mod の責任範囲です。

スケマティックのサブフォルダは、空のフォルダを含む展開可能なディレクトリとして表示されます。検索は一致するパスを自動的に展開します。ランタイムログページで **DEBUG モード** を有効にすると、HTTP リクエストの状態・ヘッダー時間、ページ遷移、タスク所要時間、転送回数、例外のトレースを確認できます。この設定は再起動後も保持されます。無効にすると新しい DEBUG イベントは生成されません。HTTP 診断はクエリ文字列、ヘッダー、応答ボディを省略します。

コミュニティリソースページでは、フィルターが検索ボックスの上に配置されます。ゲームバージョン、適用可能な Mod またはシェーダーローダー、リソースカテゴリでフィルターできます。リソースパックは機能と解像度のフィルターも公開し、シェーダーは機能とパフォーマンスへの影響を公開します。「その他のフィルター」ボタンは、環境、ソースの可用性、ライセンス、作成者、プロジェクト詳細、件数、日付、コンテンツ開示のグループ化されたオプションを含む右側のドロワーを開きます。「フィルターを適用」は最初のページから結果を更新し、「リセット」はドロワーのオプションだけをクリアします。ドロワーを閉じても入力は保持されます。「検索」または Enter で送信するか、「フィルターをリセット」を使用します。送信されたフィルターはページ送り中およびプロジェクト詳細から戻った後も有効なままです。ゲームバージョンリストは既定でリリースを表示します。「スナップショットを表示」または「エイプリルフールを表示」を有効にすると、ドロップダウンにそれらのバージョンが表示されます。この切り替えは独立して動作します。バージョンを選択して検索を送信するとリソースをフィルターできます。

### テーマプリセット

ソースセレクタで Modrinth、CurseForge、またはすべてを選択します。「すべて」は 2 つのプロバイダーから交互に結果を表示します。プロバイダー固有のカテゴリと Modrinth 限定の「その他のフィルター」ドロワーでは、対応するプロバイダーを選択する必要があります。基本フィルターは 1 行にまとめられます。CurseForge には公式リリースビルドに含まれるアプリケーション資格情報が必要です。[CurseForge 統合](docs/CURSEFORGE.md) を参照してください。

色プリセットは `themes/*.json` から読み込まれます。フレッシュグリーンが組み込みのフォールバックとして含まれています。他のパレットは外部 JSON ファイルです。WinUI3 ネイティブプリセットは引き続き Windows リソースを使用します。パレットの編集と追加については [テーマプリセット](docs/THEMES.md) を参照してください。

## サポート範囲と制限

### Frp クライアント

**詳細 → Frp クライアント** を開き、オンラインリリースリストからバージョンを選択して **オンラインでダウンロード** を選びます。**リリースを更新** でリストが更新され、**さらに読み込む** で以前のバージョンを取得します。ダウンロードは [公式 frp リリース](https://github.com/fatedier/frp/releases) から行われ、公式 SHA-256 チェックを通過する必要があります。クライアントは必要時にダウンロードされ、ランチャーパッケージには含まれません。

ダウンロードセクションはクライアントがインストールされるまで既定で開き、インストール後は折りたたみ表示になり、ヘッダーにインストール済みバージョンが表示されます。展開するとバージョンを変更またはダウンロードできます。選択した保存済みプロファイルは、別の **新規設定** と **インポート**（どちらも既定で折りたたみ）セクションより上に配置されます。作成フォーム全体（独自のコンテンツエディタと作成ボタンを含む）は新規設定セクション内にあります。インポートはコピーに成功すると閉じます。名前、形式、パスフィールドは利用可能な幅に適応します。

GitHub の API が 403/429 を返すか利用できない場合、ランチャーは公式リリース Web ページを使用し、API の再試行ウィンドウを尊重します。ダウンロードメタデータは API なしでも公式リリースアセットとチェックサムを使用できます。以前に取得したバージョンリストとリリースメタデータはランチャーデータディレクトリにキャッシュされ、両方のオンラインソースが失敗した場合にも利用できます。キャッシュまたは代替ソースはページとランタイムログで識別されます。ダウンロードには引き続き公式 SHA-256 チェックが必要です。

設定は `CMCLauncher.exe` の横の `frpc/configs/` で管理されます。ファイルまたはフォルダパスを入力し、ファイルを選択するか、フォルダを選択してコピーをインポートします。フォルダのインポートでは相対インクルード、証明書、その他の付随ファイルもコピーされます。単一ファイルのインポートでは選択した設定のみがコピーされます。元のファイルが編集されたり、Frp クライアントの起動に使用されたりすることはありません。名前が一致するインポートは個別のコピーを作成します。ページを開くと、選択された既存の外部設定がこの管理ディレクトリにコピーされます。

設定を作成するには、**新規設定** を展開し、名前を入力して INI または TOML を選択し、そのセクションに内容を入力または貼り付けてください。**設定を作成** を選択して保存し、新しいプロフィールを選択します。**現在の内容をコピー** は、選択したプロフィールの内容を変更せずに新しい下書きにコピーします。**名前を付けて保存** は現在の内容を事前に入力した同じフォームを開きます。複数のプロフィールを保持し、切り替え、編集・保存し、そのテキストを新しいプロフィールとして保存したり、確認後に保存済み設定を削除したりできます。プログラムディレクトリは書き込み可能である必要があります。ダウンロードしたクライアントと保存されたプロフィールを選択し、**検証** または **Frp クライアントを起動** を使用します。編集した内容は起動前に保存・検証されます。INI はレガシー形式です。新規設定には TOML を使用してください。クライアントのバージョンを自前の frps サーバーに合わせてください。

ランチャー内を移動している間、クライアントは実行を継続します。**Frp クライアントを停止** は管理対象プロセスとその子プロセスを終了します。ランチャーを閉じても停止します。ページには範囲が限定され、一部が難読化された出力ログが表示されます。「実行中」はプロセスが生存していることを示します。サーバー接続を確認するには Frp クライアントの出力を確認してください。自前の frps サーバーと資格情報は選択したファイルで設定します。クライアントバイナリはランチャーデータディレクトリの `tools/frpc/` に保存されます。選択したバージョンと設定パスのみがランチャー設定に保存されます。

### その他の制限

- Forge と NeoForge のインストールは可能ですが、すべてのゲームバージョンでインストールと実行時の互換性が十分に検証されているわけではありません。
- ZIP はコンテナ形式であり統合パック形式ではありません。アーカイブに認識された Modrinth、CurseForge、または MultiMC / Prism マニフェストが含まれている必要があります。
- CurseForge には承認済みアプリケーション資格情報が必要です。作成者の配布制限、利用不可ファイル、対応していないダウンロードエンドポイントはインストールを停止します。[CurseForge 統合](docs/CURSEFORGE.md) を参照してください。
- シェーダーには、インストール・有効化された Iris、Oculus、または OptiFine 環境が必要です。インポート後はゲーム内でデータパックの有効化を確認してください。
- ブラウザ認証に続けて Xbox と Minecraft サービスの検証が行われます。実際のサインインとゲーム内メニューへの到達には、有効なアプリケーション設定と実際のアカウントが必要です。ローカルテストはエンドツーエンドの検証の代わりにはなりません。
- Windows x64 がビルドと検証の対象です。ARM ネイティブの依存関係は選択されません。

## データとログ

| 場所 | 内容 |
| --- | --- |
| `%APPDATA%/CMCLauncher.Native/settings.json` | ランチャー設定、インスタンス記録、暗号化されたアカウント資格情報 |
| `%APPDATA%/CMCLauncher.Native/library/` | 既定のインスタンスと依存ライブラリ；ランチャーで別のゲームルートを選択可能 |
| `%APPDATA%/CMCLauncher.Native/runtimes/` | ランチャーがダウンロードした Java インストール |
| 実行ファイルの横の `logs/launcher-yyyyMMdd.log` | ランチャーランタイムログ |
| インスタンス内の `logs/` と `crash-reports/` | ゲームログとクラッシュレポート |

新しいデータディレクトリが存在しない場合、既存のインストールは引き続き `%APPDATA%/CraftLauncher.Native/` を使用し、アカウント、設定、インスタンスパスを保持します。

資格情報は現在の Windows ユーザーに対して DPAPI で暗号化されます。設定を別のユーザーやデバイスにコピーした場合、再サインインが必要になることがあります。ゲームをバックアップする際は、実際のインスタンスディレクトリのセーブと設定を含めてください。

SSL エラーの上書きが有効でも、ランチャーの HTTPS クライアントは組み込みの拒否リストにある証明書の公開鍵を拒否します。[CertificatePolicy.cs](native/CertificatePolicy.cs) を参照してください。このポリシーは Windows のトラストストアを変更したり、外部の Java インストーラやゲームが実行する証明書検証を変更したりしません。

## ソースから実行

Windows で、.NET 8 SDK と WinUI 3 プロジェクトの構築に必要な Windows SDK / 開発ツールをインストールします。プロジェクトは `net8.0-windows10.0.19041.0` と x64 を対象とします。クローン後、リポジトリルートで以下のコマンドを実行します。

```powershell
git clone https://github.com/com-in/CMCLauncher.git
cd CMCLauncher
dotnet run --project winui/CMCLauncher.WinUI.csproj -p:Platform=x64
```

ワンクリックのローカルビルドには、リポジトリルートの `build-and-run.cmd` をダブルクリックします。自己完結型 Release ビルドを `.artifacts/local-runs/` の新フォルダに公開し、手動テスト用にそのビルドを開きます。`dist` には触れず、ビルドエラーが見えるようにコンソールを開いたままにします。実行ごとに独自の出力フォルダが保持されます。それらのビルドを閉じた後、古いフォルダを削除できます。アプリケーションは通常のランチャー設定を使用します。

アプリケーションを開かずにビルドするには、PowerShell で `./build-and-run.ps1 -NoLaunch` を実行します。

CurseForge をローカルでテストするには、コマンドプロンプトで `build-and-run.cmd "-curseforgekey=YOUR_KEY"` を実行します。`-NoLaunch` を追加するとビルドのみ行います。スクリプトは一時的な設定ファイルを通じてキーを埋め込み、ビルド完了時（失敗を含む）にそのファイルを削除します。キーを印刷したり、`dist` を変更したりしません。

### Microsoft サインインの設定

クライアント ID のないソースビルドはインターフェースを実行できますが、Microsoft サインインは利用できません。ローカルビルドで有効にするには、設定済みの公開 OAuth クライアント ID を `winui/clientid.local.json` に作成します。

```json
{
  "clientId": "YOUR_MICROSOFT_CLIENT_ID"
}
```

プレースホルダを有効な GUID に置き換えます。このファイルは Git で無視され、コンパイル中にアセンブリリソースとして埋め込まれます。独立した JSON ファイルとして配布されることはありません。クライアント ID は公開識別子であり、クライアントシークレットではありません。アプリケーションには、適切な Microsoft / Minecraft API アクセス設定が引き続き必要です。ランチャーは Microsoft のパスワードを収集しません。

タグ付けされたリリースビルドは、この識別子を `MICROSOFT_CLIENT_ID` GitHub Actions シークレットから読み取ります。通常の PR ビルドでは書き込まれません。

### ビルドとパッケージング

Release 設定をビルドします。

```powershell
dotnet build winui/CMCLauncher.WinUI.csproj -c Release -p:Platform=x64
```

自己完結型ディレクトリを公開し、ZIP アーカイブを作成します。

```powershell
dotnet publish winui/CMCLauncher.WinUI.csproj -c Release -p:Platform=x64 -r win-x64 --self-contained true -o dist/cmc-launcher
./scripts/package-release.ps1 -PublishDirectory dist/cmc-launcher -ArchivePath dist/CMCLauncher-1.0.0-win-x64.zip
```

パッケージングスクリプトはローカル設定、資格情報、キーファイルを除外し、アーカイブにランチャー実行ファイルが含まれていることを確認します。

`./scripts/publish-singlefile.ps1` で自己解凍型の単一 EXE をビルドします。WinUI のネイティブライブラリレイアウトを変更するのではなく、検証済みのポータブルランタイムを埋め込みます。ランタイムファイルは `%LOCALAPPDATA%/CMCLauncher/singlefile/` にキャッシュされます。編集可能な言語パック、テーマ、Frp クライアント設定、ログは配布 EXE の横に置かれます。既存の言語／テーマ編集は保持されます。書き込み可能なフォルダを使用してください。`-CurseForgeConfigurationFile PATH` を渡すと、同じポータブルビルドでローカルのアプリケーション資格情報を埋め込めます。

CI は `CMCLauncher-win-x64.zip` と `CMCLauncher-win-x64.exe` の両方を生成します。タグ付けされた Release アセットのみがファイル名にバージョンを持ちます。どちらの形式も同じ資格情報注入とアーカイブチェックを使用します。単一 EXE はアップロード前に隔離された WinUI アクティベーションスモークテストも実行します。

ポータブルリリースには .NET ランタイムと必要な Windows App SDK コンポーネントが含まれるため、ユーザーはこれらのランタイムを別途インストールする必要はありません。プロジェクトは完全な Windows App SDK バンドルではなく WinUI と DWrite コンポーネントパッケージを参照し、未使用の AI、機械学習、Widget 依存関係を含めないようにしています。更新時は同じ Windows App SDK リリースの依存関係とバージョンを合わせてください。新規ディレクトリに公開してください。古い出力に上書き公開しても、古い依存ファイルは削除されません。

Release ビルドは部分的な .NET トリミングも使用します。ランチャーアセンブリと Windows/WinUI プロジェクションは完全にルート化され、リフレクションベースの JSON モデル、XAML コントロール、WinRT コレクション変換が保持されます。組み込みの COM と JSON リフレクションは有効のままです。トリミング分析の警告は表示されたままです。Debug ビルドはトリミングされません。トリミングされていない Release と比較するには、公開コマンドに `-p:PublishTrimmed=false` を追加します。

### テスト

ネイティブ回帰テストを実行します。

```powershell
dotnet run --project native.tests/CMCLauncher.Tests.csproj -c Release
```

これらのテストは Windows DPAPI を使用するため、Windows 上で実行する必要があります。最後のローカル Java 検出チェックには PATH に `java` も必要です。

アプリケーションディレクトリを公開した後、WinUI 統合チェックを実行します。

```powershell
& ./dist/cmc-launcher/CMCLauncher.exe --verify-ui "$PWD/.artifacts/winui-check"
```

このチェックは隔離されたデータディレクトリを使用し、スクリーンショットと `passed.txt` を生成します。失敗は `failure.txt` に記録されます。

## フィードバックとコントリビューション

問題は [Issues](https://github.com/com-in/CMCLauncher/issues) から報告してください。ランチャーバージョン、Windows バージョン、Minecraft とローダーのバージョン、再現手順を含めてください。起動失敗の場合は、エラーレポートまたは関連ログを添付してください。共有前にアカウント情報とローカルパスを確認してください。

プルリクエストを送る前に、変更に関連するテストを実行してください。レイアウト変更にはスクリーンショットを添付し、ダウンロード・導入・インポート機能を変更するときはキャンセルと失敗後のクリーンアップを確認してください。
